# 乐观锁（Optimistic Locking）

### 缩写：无

### 简述

假设冲突少：读时取版本号/时间戳，写时用条件更新校验版本；失败则重试或放弃。常在应用层实现，不长期持有 DB 锁。

### 使用场景

Web 表单更新、库存扣减（配合条件更新）、低冲突资源。

### 实践与应用

• UPDATE ... WHERE id=? AND version=?；影响行数 0 即冲突。
• 冲突策略：重读重试或提示用户。
• 与唯一约束等 DB 手段组合。

### 注意事项

• 高冲突场景重试风暴，应改悲观或队列化。
• 忘记更新 version 等于无保护。

### 对比与易混

乐观锁 vs 悲观锁（SELECT FOR UPDATE）；乐观锁≠隔离级别名称。

### 信号与度量

版本冲突率、重试次数。

### 相关概念与术语

悲观锁、CAS、幂等、事务。

### 深入与掌握

L1 版本条件更新；L2 完整冲突处理；L3 高冲突下的架构替代。
