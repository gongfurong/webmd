# 关系模型（Relational Model）

### 缩写：无

### 简述

用关系（表）表达数据、用键表达标识与关联、用声明式语言查询的数据模型。强调逻辑结构与物理存储分离，以及集合化运算。

### 为何出现

早期网状/层次模型依赖导航式访问，难独立于物理路径表达业务；关系模型提供数学基础与更高抽象。

### 使用场景

业务 OLTP 建模、SQL 数据库设计、与文档/图模型对比选型时的参照系。

### 实践与应用

• 先实体与关系，再落表与键。
• 查询用集合思维，少用逐行过程思维。
• 逻辑设计完成后再考虑索引与分区等物理设计。

### 注意事项

• 关系模型≠必须第三范式：可受控冗余。
• 「表」实现细节（堆/聚簇）属于物理层。

### 对比与易混

关系模型 vs 文档/键值/图模型；关系代数 vs SQL 方言。

### 局限与争议

深度层级与图遍历表达力弱于图模型；半结构化数据常需 JSON 扩展。

### 来源与线索

Codd 关系模型论文；关系代数/演算。

### 关联术语

• 表 / 键 / 约束：核心构件
• SQL：主流操纵语言
• ER 模型：设计期近亲
